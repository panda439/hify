# Phase 17：小说人物关系抽取验收报告

日期：2026-09-07。对象：010 小说场景分块与人物关系抽取。

## 实现结论

叙事上传、场景分块、异步抽取、严格引用校验、人物别名保守归一、预算与恢复、关系查询及聊天展示已经接通。Phase 3～5 的审核缺口均已修复并纳入回归。真实模型运行又发现两个提示协议问题：归一提示未列出当前 `mention_ref` 映射，以及示例使用了系统不接受的 reason code；本轮均先用失败测试固定后修复。

运行中还发现作业把配置保存为 `{}` 和全零 hash。代码现已将 prompt 版本、60 秒超时、每阶段 3 次尝试、输入输出上限及三重预算序列化并计算 SHA-256，后续作业可以复现实验配置。旧实验快照保留数据库原值，同时记录实际配置。

## 工程证据

- 计分器固定“章节 + 人物对 + 关系类型”为单位；无向关系规范化，重复关系和引用去重，失败分块计 FN，空分母输出 `null`（N/A）。
- 端到端名字与使用参考别名表后的条件指标分开报告；引用必须是标注支持范围内的原文子串。
- 参考稿覆盖 322/322 个段落 ID，共 58 条关系、102 条证据，来源检查没有缺失或错位。
- 快照保存模型 digest、语料与配置 hash、墙钟/活跃/模型耗时、确认与可能调用、usage 未知次数、原始响应及每个分块结局。
- 本地 Ollama 没有货币计费，成本口径为 `not_applicable`；没有写成 0。Ollama 兼容响应未提供完整 usage，因此 token 数保持未知。

## 真实模型效果

输入为《阿Q正传》9 章全文范围：322 个原段落，清洗后 314 段，61 个分块。两个作业都接收了完整输入清单，随后被“连续 5 个分块最终失败”保护停止。

两组 precision 均为 N/A，因为没有关系通过严格契约并发布；引用有效率同样为 N/A。主要失败是 occurrence 从 1 开始、引用被改写或不在原文、把整句识别成人物、别名决策缺项或缺少双称呼证据，以及单次调用超时。14B 的分块成功数略高，但当前证据不足以证明它的关系抽取效果更好。

这些数字只说明当前严格契约下两款本地模型无法完成这份书。参考关系仍是 AI 初稿，不能将 0% 诊断召回称为人工真值上的模型指标。

## FR / SC 验收边界

FR-001～015、FR-018～026 已有实现、测试或 Phase 5 真实 HTTP/UI 证据。FR-016 尚未完成：需要人工逐段复核并冻结真值；FR-017 已在快照和本报告标明模型、书目和规模。SC-001～005、SC-008～012 有确定性夹具或端到端证据；SC-006 已能报告本次完整输入作业的账目，但两个模型均在保护机制处停止，不能声称完成整书抽取；SC-007 等待人工金标。

## 已知边界

人工复核与来源发布许可仍待确认。当前结果不支持上线默认开启关系抽取，也不支持在面试中声称“真实模型效果已达标”。下一轮应先冻结人工验收集，再选择更可靠的结构化输出模型或调整模型适配策略；任何依据验收答案进行的提示调整都必须转为开发集并另留盲测范围。
