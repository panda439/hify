# 《阿Q正传》AI 初标 v1

已逐章阅读用户指定的 9 章材料：原 322 段中 314 段保留，8 段为网页杂项或空白。
本稿含 **58 条关系候选、32 条疑义/反例/范围记录、12 组带依据的别名记录**。
全部是 Codex AI 初标，**不是人工真值，未冻结验收，不保证穷尽**。

先看便于阅读的 [待复核表](待复核.md)，完整原文引用保留在数据文件中。

## 文件

- [关系候选](relations.jsonl)：规范人物、类型、章节、完整引用和待审状态。
- [别名](aliases.json)：别名依据及禁止直接合并的称呼。
- [疑义与反例](issues.jsonl)：需要裁定或明确排除的记录。
- [逐段覆盖](coverage.jsonl)：322 个原 ID 的阅读/排除与记录关联。
- [语料和数据快照](manifest.json)：来源路径、哈希和 AI 标注身份。
- [来源与许可记录](source-provenance.md)：候选上游 revision、许可与仍待做的逐字匹配边界。

本地语料副本在 `eval/corpus/aq-010/`，正文被该目录的 .gitignore 排除；
`narrative-only.txt` 排除 8 段杂项。保留版 ch01～ch09 是逐字原始快照，不覆盖用户材料。
引用有时需要多段联合解释，并未强行改成单块可回答，避免人为抬高抽取召回率。

## 如何复核

先裁定 `issues.jsonl`，尤其是阿Q/阿贵、吴妈事件分类、白举人雇佣自述、光头审讯者身份。
再逐章对照原文检查候选并**寻找没有列出的关系**。AI 已列出的条目不是完整检索目录。
`coverage` 的 `ai_read_pending_human_review` 表示 AI 读过，不能当人工已确认的负例。

正式评价前，每个实体还须补齐稳定 ID 和别名；本稿 alias 文件只给有明确对应依据的记录，
不把所有关系端点都伪装为已完成实体库。无向关系端点比较需规范排序。
对跨章辅助引用，主章仍按记录 chapter 判定，其他章仅作身份/上下文依据；不可当成本章发生新事件。

未经人工复核，只可用于开发或“与 AI 参考标注的一致性”实验。
满足 spec 人工真值要求，需要对完整验收范围逐段补漏、裁定并留下真实审阅记录。
不得只把文件移动到 `eval/truth/` 就声称完成。当前无真实 Qwen 效果或成本数据。


## 重建本地语料

运行 `python3 scripts/prepare-aq-corpus.py --source-dir <包含 ch01.txt～ch09.txt 的目录>`。
脚本先核对本目录 manifest 的逐章 SHA 和 coverage 的逐段 SHA，再写入被 gitignore 的 eval/corpus/aq-010。
生成 narrative-only.txt 及 source-map.json，保留 322 原 ID / 314 正文 / 8 排除，不改动本目录 AI 标注。
没有自动抓取会变化的网页；原上游 revision 与发布许可仍需补证，不能把重建当成人工标注冻结。
