# Feature Specification: 知识库试检索面板（Retrieval Playground）

**Feature Branch**: `003-retrieval-playground`

**Created**: 2026-09-02

**Status**: Draft

**Input**: 002-metadata-filter 交付了「按 document_id 与页码范围在召回阶段缩小候选范围」的
后端能力，但**没有提供任何设置过滤器的入口**——没有 HTTP 参数、没有前端、没有 Agent 配置项，
两个现有调用方（conversation / workflow）都传零值。该能力因此在生产路径上无人可用
（见 `docs/eval-phase10-metadata-filter-report.md` 第 8 节）。本期给它接上入口。

## Clarifications

### Session 2026-09-02

- Q: 入口做在哪？ → **A: 知识库页加一个「试检索」面板**。
  被否决的两个方向及理由：
  - **Agent 配置里绑定文档范围**（持久化、影响该 Agent 所有对话）：最贴合 002 spec 里
    「三个版本的手册，只想用 2026 版」那个故事，但需要改表（`agent_knowledge_bases` 加列
    或新建关联表）+ migration + Agent 表单改造，且引出「Agent 绑定的文档被删除后怎么办」
    这一类新的一致性问题。范围明显更大，单独立项。
  - **对话时临时指定范围**：最灵活，但要改 conversation 链路、SSE 协议和消息持久化语义
    （这一轮用了什么范围要不要存？重新生成时还算数吗？），三个方向里风险最高。
- Q: 这个面板的定位是什么？ → **A: 检索调试与精确查询工具，不是对话功能**。
  它回答的是「这个知识库里，限定到这些范围，我的问题能召回到什么」，
  **不产生对话、不调用对话模型、不写任何消息记录**。
  必须在界面上诚实呈现这一点，不能让用户以为自己在跟 Agent 说话。
- Q: 要不要顺带把过滤开关默认打开？ → **A: 不改默认值**。
  `HIFY_RAG_METADATA_FILTER_ENABLED` 保持默认 `false`。本期新增的端点在开关关闭且
  用户指定了范围时，必须把 002 定义的 `ErrMetadataFilterDisabled` 如实传达给用户
  （中文提示 + 说明需要开启哪个开关），**不得**静默降级成无过滤检索。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 验证「限定文档」真的有效 (Priority: P1)

用户在一个挂了多份文档的知识库里，想确认「限定到某份文档」的效果。
今天他没有任何办法触发这个能力——只能读代码或跑测试。

本功能要求：用户能在知识库页打开一个面板，输入问题、勾选若干文档、发起检索，
看到召回的片段列表（含每个片段属于哪份文档、第几页、是命中还是邻接块）。

**验收**：不勾选任何文档时召回到多份文档的片段；勾选其中一份后，
结果中 MUST NOT 出现其他文档的**命中**片段。

### User Story 2 - 验证「限定页码」真的有效 (Priority: P1)

用户上传了一份 PDF，想确认「只在第 10-15 页里找」的效果。

**验收**：填写页码范围后发起检索，结果中的命中片段 MUST 全部落在该范围内；
无页码的片段（txt/md）MUST NOT 出现在命中里。

### User Story 3 - 看得懂结果，也看得懂为什么没有结果 (Priority: P1)

用户拿到空结果时，需要能分清「过滤生效了但范围里没答案」和「我根本没写对」。

**验收**：结果为空时 MUST 有明确提示，且 MUST 区分以下情形：
过滤后无候选、知识库里没有任何已就绪的文档、功能开关未启用。

### User Story 4 - 邻接块要能被认出来 (Priority: P2)

002 的 FR-011 规定邻接块豁免 chunk 级（页码）过滤——用户会看到范围外的片段出现在结果里。
如果界面不解释，这看起来就像一个 bug。

**验收**：结果列表 MUST 在视觉上区分「命中」与「邻接块」，
并 MUST 说明邻接块是上下文补全、不受页码范围约束。

### Edge Cases

- 知识库里一份已就绪（`ready`）文档都没有 → 面板 MUST 明确提示，MUST NOT 只显示空列表。
- 用户勾选的文档在发起检索前被删除 → 沿用 002 的 FR-010：无匹配，不报错。
- 页码范围填反（起始 > 结束）或填了 0/负数 → MUST 在**前端**就拦下并给出中文提示，
  不必往返一次服务端才知道填错了；服务端仍然 MUST 独立校验（前端校验不是安全边界）。
- 勾选的文档数超过 002 的 50 份上限 → MUST 给出明确错误，MUST NOT 静默截断。
- 问题为空 → MUST 不发起请求。

## Requirements *(mandatory)*

### Functional Requirements

**后端**

- **FR-001**: MUST 新增一个检索端点，接受「问题 + 可选文档 ID 列表 + 可选页码范围 + 可选 topK」，
  返回召回的片段列表。
- **FR-002**: 该端点 MUST 复用 `knowledge.Service.Retrieve` 与 002 的 `RetrieveOptions`，
  MUST NOT 另起一条检索实现——两条检索路径会立刻分叉，且让 002 的全部断言失去意义。
- **FR-003**: 该端点 MUST 只在**单个**知识库内检索（路径参数 `:id`），
  MUST NOT 接受跨知识库的 ID 列表——那是 conversation 的语义，不是本面板的。
- **FR-004**: 返回的每个片段 MUST 携带：片段 ID、所属文档 ID 与文档名、页码（可能为空）、
  分数、是否为邻接块。
- **FR-005**: 该端点 MUST NOT 调用任何对话模型、MUST NOT 创建会话或消息记录、
  MUST NOT 写入 `trace_spans`——它不是一次对话。
- **FR-006**: 002 定义的三个过滤错误（超限 / 页码非法 / 开关未启用）MUST 原样传达到 HTTP 响应，
  MUST NOT 被吞掉或转成空结果。
- **FR-007**: topK MUST 有上限，沿用既有的 `clampTopK` 语义。

**前端**

- **FR-008**: 知识库列表页 MUST 提供进入该面板的入口。
- **FR-009**: 面板 MUST 能列出该知识库下**已就绪**的文档供勾选，MUST 显示文档名而不是 ID。
- **FR-010**: 面板 MUST 支持填写页码范围的上下界，两端 MUST 都可留空。
- **FR-011**: 结果 MUST 区分命中与邻接块，MUST 显示来源文档名与页码。
- **FR-012**: 界面 MUST 明确这是检索调试工具、不是对话——MUST NOT 出现会让用户以为
  在跟 Agent 对话的措辞。
- **FR-013**: 后端返回的错误 MUST 以中文呈现给用户，MUST NOT 只在控制台打印。

### Key Entities

- **试检索请求（Retrieval Probe Request）**：一次性的、无状态的检索查询。不持久化。
- **试检索结果（Retrieval Probe Result）**：片段列表 + 足以解释「为什么是这些/为什么为空」的
  少量计数。不持久化。

## Success Criteria *(mandatory)*

- **SC-001**: 在真实运行的服务上，通过界面完成一次「限定文档」的检索，
  结果中不含其他文档的命中片段。
- **SC-002**: 在真实运行的服务上，通过界面完成一次「限定页码」的检索，
  结果中的命中片段全部落在范围内。
- **SC-003**: 新端点有集成测试覆盖：文档过滤生效、页码过滤生效、
  002 的三个过滤错误如实返回、不产生任何会话/消息/trace 记录。
- **SC-004**: 002 的确定性检索门禁 MUST 保持通过且既有用例逐字段不变——
  本期不得改变任何既有检索行为。

## Assumptions

- 002 的 `Retrieve(ctx, kbIDs, query, topK, opts)` 签名与语义不变，本期只是它的第一个真实调用方。
- 本期不新增 migration：试检索不持久化任何东西。
- 权限沿用知识库既有模型（登录用户皆可检索自己看得见的知识库），本期不新增权限维度。

## Out of Scope

- **Agent 配置里绑定文档范围**、**对话时临时指定范围**（见 Clarifications 的否决理由）。
- 由 LLM 从问题中自动抽取过滤条件（002 已排除，仍然排除）。
- 把试检索结果导出、保存或分享。
- 在面板里展示 RRF 分数构成、准入判定过程等内部细节——只展示最终结果与来源。
- 改变 `HIFY_RAG_METADATA_FILTER_ENABLED` 的默认值。
