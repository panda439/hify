## 2. 测试 PDF 夹具清单

### 2.1 ⚠️ 前置任务：`writeTestPDF` 必须先被扩展

`internal/knowledge/structure_test.go:761` 的 `writeTestPDF` 目前把**整页文本作为单个 `Tj`
放在固定坐标 `72 700 Td`、固定字号 12**（`BT /F1 12 Tf 72 700 Td (...) Tj ET`）。
后果是所有字形同一个 Y、同一个字号、同一个起始 X。

**这意味着它目前造不出下面 8 份夹具里的任何一份**：

| 造不出什么 | 挡住了哪条判据 |
|---|---|
| 多行 | 噪音的**位置**判据（顶部/底部 Y 带）——一页只有一行时"顶部"和"底部"是同一行 |
| 不同字号 | 标题的**字号信号**（R5 第 1 条）、合并判据第 2 条的"字号未显著大于正文" |
| 不同行宽 | 合并判据第 3 条的"接近满行宽"——所有行等宽时这条判据恒成立或恒不成立 |

**最小扩展**：每行一个 `Td`（逐行定位，Y 递减）+ 可选的 `Tf`（逐行字号）。
接口大致是从 `pages []string` 变成 `pages [][]testLine`，`testLine{Text, FontSize}`，
Y 由行序自动递推。仍然只支持纯 ASCII（`(`/`)`/`\` 需要 PDF 字符串转义，helper 不实现，也没必要）。

⭐ **这必须是 `tasks.md` 里的一个独立前置任务**，不能散落进各个测试任务里——
它是下面每一份夹具的共同前提，八个任务各自扩一点会立刻冲突。

### 2.2 夹具清单

| # | 夹具 | 构造要点 | 验证什么 | 对应 |
|---|---|---|---|---|
| **F1** | **跨页段落** | ≥5 页；第 3 页末行**不以句末标点结尾**、**接近满行宽**、**不是列表/标题**；第 4 页首行是它的续写 | 两半合并进**同一个**片段；该片段 `page_number=3, page_end=4`；overlap 能跨页携带 | **SC-001**、FR-001/002/010 |
| **F2** | **固定页眉页脚** | ≥5 页（**必须高于最小页数门槛**）；每页顶部同一章节名，每页底部「第 X 页 / 共 Y 页」；正文各页不同 | 产出片段中页眉页脚文字出现次数为 **0**；审计日志记录了剥离项与原因 | **SC-002**、FR-005/006/008 |
| **F3** | **单页** | 1 页正文，无页眉页脚 | 无跨页合并可做；噪音判定被页数门槛跳过；产出**与改动前一致** | Edge Cases、FR-009 |

| **F5** | **部分扫描件** | 5 页里 2 页无文本、3 页有文本 | 有文本的 3 页**正常入库**（不整体失败）；页码归属仍指向真实页号（跳过的页不导致页码错位）；告知用户的承载方式**待拍板** | FR-018 |
| **F6** | **无句末标点的列表型** | ≥4 页；每行形如「1. 某项」，**全篇无句号**；跨页连续 | **不得**被合并成一个超长段落；`chunk_size` 硬上限仍生效；合并判据第 2 条（列表项）挡住它 | Edge Cases、FR-003/004 |
| **F7** | **仅两页** | 2 页，两页**都**带相同页眉 | **跳过**基于重复率的噪音判定，页眉**不**被剥离——宁可漏剥，不可误删（两三页统计不出可信重复率） | **FR-009**、Edge Cases |
| **F8** | **标题层级**（P3，**可裁**） | ≥3 页；「1. 」「1.1 」编号 + 字号显著大于正文的标题行 | 标题下方片段携带 `section_title`；识别不出时**留空而非编造** | US4、FR-015/016 |

⚠️ **两条边界情况没有专门夹具，是有意的**：

- **"页眉页脚与正文文字完全相同"**（spec 的 Edge Cases）——这条由 F2 的判据交集天然覆盖：

- **"文档页数极多"**——由 §1.3 的性能基线覆盖，不需要单独的正确性夹具。

```bash

python3 scripts/compare-retrieval-gate.py /tmp/gate-baseline-006.json eval/runs/phase6-retrieval-gate-latest.json
```

**MUST 输出 `IDENTICAL`。**

门禁语料是 txt / md，**不含 PDF**——这正是它能证明 SC-006 的原因：
它度量的是"非 PDF 路径的检索行为一个字都没变"。比对时忽略 `ran_at`（每次运行都不同），
其余字段逐字节相同。

⚠️ **本功能不给门禁新增用例**。002 当时新增了两条用例并因此放宽了比对规则（允许 cases 变长），
本功能没有这个需要：它的新行为全部在 PDF 路径上，而门禁语料里没有 PDF。
**因此这次的比对可以是最严格的形态：cases 数组长度都不许变。** 如果它变了，说明有人在
不相关的地方动了门禁，那本身就是要查的事。

### 3.5 ⚠️ 禁止用 `make eval` 证明行为未变

**`make eval` 不是本功能的验收手段，一次都不要跑来当证据。**

宪法「技术栈与工程约束」写死了这条：`make eval` 的每条用例都要调**真实对话模型与裁判模型**，
**同一份代码跑两次都不会一致**。用一个自己都不可复现的东西去证明"行为未变"，
得到的不是证据而是噪音——数字往好的方向抖一下就会被当成"改进了"，往坏的方向抖一下就会
引出一轮根本不存在的 bug 排查。

`make eval` 只在接入真实嵌入 / 重排模型后，用于**度量相对提升**，与本功能无关。

### 3.6 性能对照（SC-008）

```bash
go test ./internal/knowledge/ -run '^$' -bench 'BenchmarkPDFExtractAndChunk' -benchtime 20x -count 5 \
  2>&1 | tee /tmp/perf-after.txt
benchstat /tmp/perf-before.txt /tmp/perf-after.txt   # 没有 benchstat 就人工比中位数
```

判据：抽取 + 分块阶段的耗时增幅 **≤ 50%**。
⚠️ 噪音识别需要跨页统计，必须是 **O(总行数)** 而不是 O(页数²)——
如果增幅随页数增长而恶化，那不是"稍微慢了点"，是算法复杂度选错了，要回头改实现而不是调阈值。

## 4. 逐条成功标准的验证方式

| SC | 怎么验 | 夹具 |
|---|---|---|
| **SC-001** 跨页内容能被一次检索命中且形态完整 | 集成测试：F1 入库 → 就该段落检索 → 断言存在一个**包含完整段落**的片段。⭐ **必须先看到它在改动前 FAIL**（§1.2） | F1 |
| **SC-002** 页眉页脚出现次数为 0 | 入库 F2，遍历全部产出片段，断言页眉文字与页脚文字的出现次数**都是 0**（不是"很少"） | F2 |
| **SC-003** 页码区间 100% 合法 | 遍历全部产出片段断言 C1/C2/C3；外加数据库 `chunks_page_range_valid` 约束兜底（§3.2） | 全部 |
| **SC-004** 同一 PDF 连续处理两次逐字节一致 | 同一份 F1 连跑两次 `chunkDocument`，断言片段序列与页码归属**逐字节相同**。⭐ 这条专盯 map 迭代顺序坑，见 §4.3 | F1 / F2 |
| **SC-005** 正文误删率 0 | 纯函数单测：构造只出现在**单页**的内容，断言噪音判定对它一律返回"不剥离"，**穷举位置维度**（页顶 / 页中 / 页底都试） | 纯函数 |
| **SC-006** 非 PDF 行为完全一致 | `make eval-retrieval-gate` 输出 `IDENTICAL`（§3.4）；外加 txt/md 分支的 `chunkPiece` 两个页码字段恒为 nil 的断言 | 门禁语料 |
| **SC-007** 扫描件提示可行动 | 入库 F4，断言错误码是 `knowledge.pdf_no_text_layer`、Message 中文且**与 `ErrEmptyContent` 的文案不同**；再入库一个真正的空文件，断言它仍走 `knowledge.empty_content` | F4 |
| **SC-008** 处理时间增幅 ≤ 50% | §3.6 的 benchmark 对照，口径 = 抽取 + 分块 | 多页夹具 |

### 4.1 SC-004 的确定性用例要盯什么

不是随便跑两次看结果一样就行——**map 迭代顺序的 bug 可能几十次才复现一次**。用例要：

- 对**同一个** `[]pdfLine` 输入连续调用判定函数 **20 次以上**，断言每次结果完全相同
- 特别覆盖**行宽众数存在并列**的输入（两个桶计数相同）——那正是 tie-break 唯一会被触发的地方，
  也是"排序后迭代"这条规则唯一真正起作用的场景
- 特别覆盖**重复率统计存在并列**的输入

### 4.2 SC-005 的用例要穷举什么

「宁可漏剥，不可误删」的验证形态不是"跑一份文档看着没删错"，而是**穷举判据的每一个维度各失效一次**：

| 输入 | 期望 |
|---|---|
| 位置在页顶、但只出现在单页 | **不剥离**（重复判据不成立） |
| 跨页高度重复、但位于页面中部 | **不剥离**（位置判据不成立） |
| 位置在页顶且跨页重复、但长度接近正文行宽 | **不剥离**（长度判据不成立） |
| 三条同时成立 | 剥离 |
| 整行只有数字 / 匹配「第 X 页」「Page X of Y」 | 剥离（纯页码行是独立规则，不要求满足上述三条） |
| 文档页数低于门槛 | **不剥离**（无论前三条是否成立） |

前三行是 SC-005 的真正内容：**任何单条判据成立都不足以剥离**（FR-007）。

### 4.3 变异测试（确认断言真的有牙齿）

一组"测试全绿"本身不证明任何事——测试可能根本抓不到 bug。至少注入下面几种缺陷各跑一次，
**确认对应用例真的会失败**，跑完务必还原：

| 注入的缺陷 | 应当失败的用例 |
|---|---|
| 让跨页合并判定恒返回 `false`（退回按页切分） | SC-001 用例 |
| 让跨页合并判定恒返回 `true`（无条件合并所有页） | F6（列表型不得被合并）+ 长度上限用例 |
| 让噪音判定恒返回 `true` | SC-005 的全部单测 |
| 让噪音判定的三条判据从「与」改成「或」 | SC-005 的前三行 |
| 把行宽众数改回直接 `range` map | SC-004 的确定性用例（⚠️ 若跑 20 次仍不失败，说明次数不够，加到 200 次） |
| 把过滤 SQL 的下界谓词写回 `page_number >= min` | 跨页片段的区间相交用例（contracts §3.3 的三个 ⭐ 格） |
| 给页码谓词加上 `OR page_end IS NULL`（"无元数据即通过"）——**两侧各试一次** | NULL 页码排除用例。**必须单侧也试**：只测闭区间时单侧的错误会被另一侧未改动的谓词掩盖掉，用例照样通过（002 实际踩过这个盲区） |
| 在四处行映射里漏掉一处的 `page_end` | 对应路径的 R3 断言（尤其是邻接块那一处） |

   （代码路径 + 断言），只有 SC-008 的 benchmark 属于度量，且它的口径是抽取 + 分块而非端到端。
3. **`extractPDFPages` 的换行阈值仍是未修复的魔数**，行切分不可靠会传导到噪音判定——
   这是本次改动**没有解决**的已知缺陷，不能因为周边变好了就不提。
