# Phase 0 · 技术调研与关键决策：PDF 版面感知解析与跨页分块

**Feature**: `006-pdf-layout-chunking` | **Date**: 2026-09-04

本文解决 `spec.md` 遗留的两项开放决策（D-001 / D-002），并把五处启发式判据的取值理由固定下来，
供 `plan.md` 与 `tasks.md` 引用。

---

## R1 · 解析路线（对应 spec 的 D-001）

**Decision**：**在 Go 进程内基于排版特征做启发式实现**，不引入外部文档解析器。

**Rationale**：

1. 本功能的两个 P1 用户故事（跨页合并、噪音剥离）**不需要视觉版面检测模型**。它们依赖的信号——
   行的 Y 坐标、行文本、跨页重复率——`rsc.io/pdf` 已经能提供（`parse.go` 现在就在用 X/Y 做换行重建，
   只是把 `FontSize` 扔掉了）。**为两个不需要模型的能力引入一整条外部依赖，收益与代价不成比例。**
2. 宪法「技术栈与工程约束」写明前端 `go:embed` 打包进单个 Go 二进制。外部解析器（Python 生态）
   会引入进程外依赖或服务调用，**直接破坏这条约束**，需要在复杂度追踪里论证——而 P1 根本用不上它。
3. 唯一真正受这条决策拖累的是 US4（标题识别，P3，SHOULD）。规格已允许它被裁掉或降级。

**Alternatives considered**：

| 方案 | 优势 | 否决理由 |
|---|---|---|
| 外挂 Docling / MinerU 把 PDF 转成带结构的中间格式，再走既有 Markdown 分块通道 | 版面还原质量显著更高（业界普遍用视觉版面检测模型而非排版启发式）；标题、表格、阅读顺序都能拿到 | 破坏单二进制约束；引入 Python 运行时与模型权重；**对 P1 没有增益** |
| 换更强的 Go PDF 库 | 不破坏单二进制 | Go 生态没有带版面分析能力的成熟库；换库本身是范围外的大改动 |
| 保持现状，只在检索侧用邻接窗口补救跨页断裂 | 改动最小 | 邻接窗口按 chunk 相邻扩展，**跨页断裂的两半在语义上仍各自不完整**，补不回被截断的句子；且完全不解决噪音污染 |

**已知能力上限（必须写进验收报告）**：本方案的标题识别质量、复杂排版适应性**明显低于**基于视觉版面
检测的业界方案。这是一个知情的取舍，不是"做到了同等效果"。

## R2 · 页码区间的存储与过滤语义（本功能最关键的设计点）

**Decision**：

- `chunks` 表**新增一列 `page_end`**，保留 `page_number` 并把它的语义收紧为**起始页**。
- 不变量：`page_end IS NULL` ⟺ `page_number IS NULL`；有值时 `page_number <= page_end`。
- 元数据页码过滤（002-metadata-filter）从**点落区间**改写为**区间相交**：
  - 现状：`page_number >= min AND page_number <= max`
  - 改后：`page_end >= min AND page_number <= max`

**Rationale**：

⭐ **这个改写对所有存量行和所有单页片段是逐字节等价的。** 当 `page_end = page_number` 时，
`page_end >= min AND page_number <= max` 与 `page_number >= min AND page_number <= max` 完全等价。
因此：

- 存量数据只需一次 `page_end = page_number` 的回填，行为不变
- 非 PDF 文档（`page_number` 为 NULL）仍然由 SQL 三值逻辑保证"设了任一端就不匹配"，语义不变
- **只有真正跨页的新片段会表现出新行为**，而那正是我们想要的：过滤"第 4 页"应当命中一个覆盖 3-4 页的片段，
  因为它确实包含第 4 页的内容

⚠️ 沿用 000003 迁移注释里那条禁令：**禁止用 `COALESCE(page_number, 0)` 之类的写法给 NULL 页码兜底**——
那等于给一个本来没有页码的片段编造页码。新增的 `page_end` 同样适用。

**Alternatives considered**：

| 方案 | 否决理由 |
|---|---|
| 把 `page_number` 重命名为 `page_start` | `page_number` 已在 DB、sqlc 生成代码、`dto.go`、前端四处使用；重命名是纯改名成本，收益仅命名美观，违反宪法第 IX 条最小范围 |
| 用一个 `pages int[]` 数组列存实际覆盖的所有页 | 表达力过剩——片段覆盖的页必然连续；数组列让过滤 SQL 和索引都复杂化 |
| 跨页片段仍记单页（取起始页） | 违反 FR-011，且这正是现状回避的问题：**任选一个页码就是不诚实** |

## R3 · 跨页段落合并判据

**Decision**：上一页末行与下一页首行合并，当且仅当**同时**满足：

1. 上一页末行**不以句末标点结尾**（`。．！？；：.!?;:` 及其全半角变体）
2. 上一页末行**不是列表项或标题**（不匹配 `^\s*\d+[.、)]`、`^\s*[-*·]`、`^第.{1,3}[章节条]`，且字号未显著大于正文）
3. 上一页末行**接近满行宽**——其渲染宽度不低于该页正文行宽众数的一个比例阈值（说明它是被排版换行截断的，
   不是段落自然结束）

**Rationale**：三条判据分别排除三类假阳性——句子已结束、结构单元边界、段落自然短行结尾。
**必须三条同时成立**，因为任何单条都容易误判（例如中文文档里不加句号的标题行会同时满足第 1 条）。

**取舍方向（沿用 spec 的 Assumptions）**：**倾向合并**。代价不对称——错误合并最多让一个片段包含两个主题
（下游还有准入与重排兜底），错误切断则直接导致内容检索不到，且**无法在下游任何环节补救**。

**Alternatives considered**：用语言模型判断段落是否连续——违反宪法第 V 条的成本取向（入库路径引入 LLM 调用
会让处理时间和成本随文档页数线性增长），且与本功能"不引入模型"的定位冲突。

## R4 · 版面噪音（页眉页脚）识别判据

**Decision**：一行被判为噪音，当且仅当**同时**满足：

1. **位置**：位于页面顶部或底部的 Y 带内
2. **重复**：归一化（抹掉数字）后的文本在文档中出现的页数占比 ≥ 阈值
3. **长度**：行长度显著短于该页正文行宽

外加一条独立规则：**纯页码行**（整行只有数字，或匹配"第 X 页 / X / Y / Page X of Y"一类模式）直接判为噪音，
不要求满足上述三条。

**门槛**：文档页数低于最小页数门槛时，**跳过基于重复率的判定**（FR-009）——两三页的文档统计不出可信的重复率。

**Rationale**：三条判据取交集是为了**把假阳性压到接近零**。规格 SC-005 要求正文误删率为 0，
方向明确是**宁可漏剥**。位置或重复率任一单独使用都会误伤（每页开头的正文段落满足位置，
文档里反复出现的固定术语行满足重复）。

**审计要求**（FR-008）：被剥离的内容必须落结构化日志，含所属页码与剥离原因。
⚠️ 按宪法第 VII 条，日志读者是开发者，用英文；且**不记录正文内容本身**以外的敏感信息（本场景无凭据类数据）。

**Alternatives considered**：用固定的"每页跳过首行末行"——最简单也最粗暴，对无页眉的文档等于直接删正文，
与 SC-005 直接冲突。

## R5 · 标题识别（US4，P3）

**Decision**：**双信号交叉验证**，两个信号都命中才判为标题：

1. **字号信号**：该行字号显著大于全文正文字号众数
2. **模式信号**：匹配常见标题编号模式（`1.` / `1.1` / `第三章` / 全大写短行）

识别出的标题按既有 `chunkMarkdown` 的标题栈逻辑，作为 `section_title` 附加给其下方片段。

**Rationale**：单靠字号会把强调文字（加粗大字的引用、封面文字）误判为标题；单靠模式会漏掉不带编号的标题。
交叉验证牺牲召回换准确——**符合 FR-016「识别不出就留空，不编造」的方向**。

**降级**：无法可靠识别时 `section_title` 保持 NULL。这与现状（PDF 从不产出 `section_title`）一致，
**因此 US4 完全裁掉也不会破坏任何既有行为**。

## R6 · 扫描件识别与提示

**Decision**：在抽取阶段统计"有可提取文本的页数 / 总页数"：

- 比值为 **0** → 返回新的专用错误：明确指向"无文本层的扫描件，需要 OCR"（中文，按宪法第 VII 条）
- 比值介于 0 与 1 之间 → **正常处理有文本的部分**，并在处理结果里告知有页面未能提取（FR-018）
- 比值为 1 → 无提示

**Rationale**：现状是所有页无文本 → `pieces` 为空 → `ErrEmptyContent`「文档内容为空或无法提取到文本」。
这个提示**已经不是静默失败**，但它无法让用户区分"传了个空文件"和"传了份扫描件"。
本项改动成本极低（一次计数 + 一个新错误），收益是把困惑变成可行动的下一步。

**明确不做**（FR-019）：OCR、视觉检索（ColPali 一类把页面当图像做多向量嵌入）。
后者是与文本抽取并行的**另一条完整流水线**——需要 VLM 推理、多向量存储、生成侧多模态模型，
不属于本功能范围。

## R7 · 存量数据处理（对应 spec 的 D-002）

**Decision**：**只回填，不重建。**

- 迁移中执行 `UPDATE chunks SET page_end = page_number`（含 NULL 行，NULL 回填仍为 NULL）
- 新分块逻辑**只对新入库或被重新处理的文档生效**
- 不主动重跑存量文档的分块

**Rationale**：

1. 由 R2 的等价性，回填后**存量行的检索与过滤行为逐字节不变**（满足 FR-022 与 SC-006）
2. 重建存量文档意味着重新调用 embedding——成本随存量线性增长，且属于范围外的数据迁移工程
3. 用户对某份文档不满意时，**重新处理该文档**就能享受新逻辑，这是既有能力，无需新建入口

**Alternatives considered**：迁移时批量重建全部 PDF 文档——被否决，理由是成本不可控且违反宪法第 IX 条最小范围。

## 判据阈值的统一约定

R3、R4、R5 涉及若干数值阈值（行宽比例、重复率、字号倍数、最小页数）。约定：

- **全部定义为包内常量，不做运行时可配置**——它们是启发式的实现细节，暴露成配置只会把调参责任推给用户
- **每个常量的文档注释必须写明取值理由和它在防什么**，与 `admission.go`、`toolloop.go` 既有风格一致
- **全部判定逻辑必须是不依赖数据库、不依赖 PDF 库的纯函数**（宪法第 V 条），输入是行结构切片，输出是判定结果
