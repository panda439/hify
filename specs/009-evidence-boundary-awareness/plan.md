# Implementation Plan: 让模型知道自己证据的边界

**Branch**: `009-evidence-boundary-awareness` | **Date**: 2026-09-05 | **Spec**: [spec.md](./spec.md)

## Summary

对话链路上模型对"自己手里的证据有多完整"完全无知，两个层面：

1. **空检索完全静默**。`assembleContext` 现在「有证据就注入引用规则 + `<retrieved_sources>`，
   没证据就什么都不注入」，而"没证据"包含没绑库 / 检索失败 / 确实无匹配三种截然不同的情况，
   在模型眼里长得一模一样。它于是按参数知识作答，语气与有依据时毫无区别。
2. **资料不完整时模型不知道**。007/008 记录了哪些页没进知识库，但那个事实只到文档列表为止。

本期加两处注入：**检索执行且无匹配时**告诉模型这个事实；**命中文档不完整时**把这件事随
资料交给模型。路线由 [research.md](./research.md) 定死：只有"确实无匹配"注入（R2）；
按文档去重的一条汇总说明、批量取数（R3）；结构上与不可信资料区分（R4）；计进预算（R5）。

⚠️ **本功能不改善检索，也不让任何内容进入知识库。** 它只让模型知道边界在哪。

## ⭐ Technical Context 里最要紧的一条：本期测不了它想改善的东西

前三期（006/007/008）的成功标准全是可判定的。**本期不是。**

主要风险——模型对本来答得很好的问题也开始加免责声明——落在本仓库**唯一没有度量的地方**：
`make eval` 带 LLM 裁判、同一份代码跑两次都不一致（宪法禁止拿它当证据），
确定性门禁只覆盖检索不覆盖回答。

**R1 的答案是三条**：① 承认只有机制证明并写进报告；② **把上下文组装纳入确定性门禁**
——这是本期唯一新增的可度量能力，价值超出本期本身；③ 注入文本**只陈述事实、不给行为指令**，
因为给指令等于主动诱导对冲，而我们没有能力发现它已经发生。

### 已知范围边界

1. **"过度声明不确定"这个风险没有度量，只有缓解**（R1 第 3 条：只陈述事实不给指令）。
   报告不得写成"已验证无副作用"，只能写"已把注入面压到最小，且无法度量"。
2. **检索失败与没绑知识库对模型不可区分**（R2 的已知代价）。两种情况下我们手里都没有
   为真的话可说，沉默好过说一句不确定为真的话。
3. **新增的上下文门禁只覆盖 `assembleContext` 的产出**，不覆盖模型的回答。
   它证明"送出去的东西是我们打算送的"，不证明"送出去之后效果更好"。

## 降级与失败矩阵

| 情形 | 行为 | 依据 |
|---|---|---|
| 没绑知识库 | 不注入任何信号，逐字节同改动前 | FR-002 / SC-004 |
| 检索失败降级为空 | **不注入**——无从断言任何事 | FR-003 / R2 |
| 检索执行、无匹配 | 注入"已检索、无匹配"的事实陈述 | FR-001 / SC-001 |
| 有证据、命中文档均完整 | 逐字节同改动前 | FR-004 / SC-003 |
| 有证据、部分文档不完整 | `<retrieved_sources>` 内加一条按文档去重的汇总说明 | FR-005 / SC-002 |
| ⚠️ **取缺页信息的查询失败** | **静默降级为不注入说明**，资料照常送、对话照常进行 | 宪法第 V 条：一个展示性的补充信息绝不能拖垮对话 |
| 缺页信息不可知（存量 / 非 PDF） | 不附加说明 | FR-008 |
| 多轮，部分轮有证据 | 逐轮判断，不残留 | FR-011 |
| 预算极度紧张 | 新增字符与既有项一起参与截断核算，不特殊优待 | FR-010 |
