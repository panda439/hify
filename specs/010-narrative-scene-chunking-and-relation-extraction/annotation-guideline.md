# 真值集标注口径（D-003 的裁定）

**Feature**: `010` | **Date**: 2026-09-06 | **语料**：《阿Q正传》全 9 章、322 段、22,617 字

> ⚠️ **这份口径必须在任何 prompt 调优之前冻结**（FR-016）。冻结之后再改口径，
> 前后的数字就不可比——要改，就重新标、重新算，并在报告里写明换过口径。

---

## 0. ⛔ 三条禁令（违反其一，整个真值集作废）

1. **禁止用模型输出当标注底稿。** 必须从原文标。
   人在改稿时只会删错的、改歪的，**几乎不会补模型压根没想到的**——真值集会被系统性
   塑造成"模型能找到的关系"，**召回率因此被严重高估，且高估得毫无痕迹**。
2. **禁止边标边调 prompt。** 标注完成并冻结之前，不看模型跑出来什么。
3. **禁止只标"好标的"章节。** 全 9 章都要标。挑着标会让分母失真。

---

## 1. 标什么

**只标人物与人物之间的关系。** 不标人-物、人-地、人-组织。

一条关系成立的判据：**原文有明确支持**。需要推理三步才能得出的，不标。
⚠️ 拿不准就**不标**——漏标会压低召回率（可解释），错标会污染精确率（不可解释）。

## 2. 关系类型（封闭集合，不得自创）

| 类型 | 含义 | 方向性 |
|---|---|---|
| `雇佣` | 一方雇/使唤另一方做工 | 有向：雇主 → 被雇者 |
| `亲属` | 血缘或姻亲 | 无向 |
| `同乡邻里` | 同村、邻居、街坊 | 无向 |
| `冲突` | 争吵、斗殴、结怨 | 无向 |
| `欺凌` | 一方压迫/羞辱另一方 | 有向：施加者 → 承受者 |
| `追求` | 一方对另一方求爱/求亲 | 有向：追求者 → 被追求者 |
| `权势压迫` | 一方以地位/权力压制另一方 | 有向：上位 → 下位 |
| `同伙` | 一起行动、共谋 | 无向 |

**封闭集合是刻意的**：开放集合会让"同义判定"变成无穷争论，
而那正是让指标失去意义的方式。类型不够用时，**标 `其他` 并在备注里写清**——
`其他` 在计算时**单独统计，不计入主指标**。

## 3. 方向约定

有向关系一律记作 **`subject` 对 `object`**：

- 「赵太爷雇阿Q做短工」→ `subject=赵太爷, object=阿Q, type=雇佣`
- 「阿Q调戏吴妈」→ `subject=阿Q, object=吴妈, type=追求`

⚠️ **方向错算作错**（FR-016 明列）。「A 是 B 的师父」和「B 是 A 的师父」是两条不同的事实。

## 4. 人物与别名

同一人物用**一个规范名**（如 `阿Q`），所有称呼记进别名表：
`阿Q / 阿贵 / 老Q / 阿Quei`。

⚠️ **拿不准是不是同一个人，就当两个人标**（对应 FR-013「宁可碎，不可错合」）。
真值集里的错误合并，会让被测系统的正确行为被判成错。

## 5. 出处

每条关系记 **段落 ID**（`C04P017`）。一条关系在多段都有支持时，**每段各记一条**——
它们在计算时按「同一三元组 + 不同出处」去重为一条，但**出处集合**用于验证
FR-025（引用必须与原文可校验匹配）。

## 6. 章节

段落 ID 前缀即章节号（`C04` = 第 4 章）。**章节表示叙述顺序，不是故事时间**
（FR-008 明文）——倒叙、回忆里的事件，章节号仍按它出现的位置记。

## 7. 计算口径

一条抽出的关系**算命中，当且仅当四项全对**：

1. 两个实体都归到真值集里的同一人物（经别名表）
2. 关系类型落在同一类型（`其他` 不计入主指标）
3. **方向正确**（无向类型忽略此项）
4. **出处能在原文中定位到**

- **精确率** = 命中数 / 抽取产出的关系总数
- **召回率** = 命中数 / 真值集关系总数
- **统计范围限定在被完整标注的章节内**；本期全 9 章都标，因此**没有"未标注章节"这个豁免**
- 分母为零报 **N/A**，不报 0

## 8. 输出格式

`eval/truth/aq-relations.jsonl`，一行一条：

```jsonl
{"subject":"赵太爷","object":"阿Q","type":"雇佣","evidence":["C02P011"],"note":""}
{"subject":"阿Q","object":"吴妈","type":"追求","evidence":["C04P021","C04P023"],"note":""}
```

别名表 `eval/truth/aq-aliases.json`：

```json
{"阿Q": ["阿Q","阿贵","老Q","阿Quei"], "赵太爷": ["赵太爷","赵老太爷"]}
```

---

## 9. ⚠️ 这份口径本身是一种选择

关系类型怎么划、方向怎么定、"明确支持"的门槛在哪——**换一套划法，数字就会变**。
这不是可以回避的缺陷，只能写清楚。**报告里必须承认：精确率是"在这套口径下"的精确率**，
不是某种客观真值。
