# Phase 5 真实 HTTP/UI 冒烟证据

日期：2026-09-07

## 环境

- 当前工作树构建的 Hify 服务，监听 `127.0.0.1:18080`
- 隔离 MySQL/PG 数据库 `hify_smoke_010`，复用本地 Redis 测试实例
- Fake OpenAI-compatible SSE 服务，仅用于稳定验证生成成功与连接故障
- 独立管理员、Agent、会话、知识库、两本文档和两个抽取 job；未使用开发库业务数据

## UI 验证

| 场景 | 结果 |
|---|---|
| 默认关闭 | 新开/刷新对话后“问人物关系”默认未勾选 |
| 参数不完整 | 勾选后未选书或未填两个人物时发送按钮禁用，并显示填写提示 |
| 同名歧义 | 输入“老王/阿Q”后显示两个结构化候选：原文第 100、9000 字符处 |
| 选择候选 | 点击第一个“老王”后回填对应 ID，再次发送不再歧义并进入关系查询 |
| 状态隔离 | 切换或新建会话清空关系选择；后台书目失效后清除旧选择 |

## 真实 HTTP/SSE 验证

| 场景 | 观察结果 |
|---|---|
| 普通对话 | 请求不带 `relation`，仅走既有生成链路，收到 `delta → final → done` |
| 禁用 | 禁用文档不会进入可查询书目；直接请求返回范围外提示，不泄露关系数据 |
| 未开始 | 启用但无 active job，返回“还没有做过人物关系抽取”固定提示 |
| 部分完成 | running job 的 2 个片段完成 1 个，返回“还有 1 个片段没有处理” |
| 完成但无记录 | succeeded job 返回明确的“没有找到记录”固定提示 |
| 模型故障 | 已检索到证据后关闭 Fake Provider，SSE 返回 `retrieval → error`，未伪装为空结果 |
| 同名歧义 | 先发 `relation_candidates`，再发固定澄清文本及 `final → done`；候选包含 ID、原文顺序和 subject 侧别 |
| 两章关系变化 | 同一人物对的第 1、2 章关系按原文顺序形成 S1/S2；生成结果引用 `[S1]`、`[S2]`，final 中保存两条经 PG 原文核验的 citation |
| 范围外文档 | 返回“当前助手可访问的文档范围里没有这份资料” |
| 跨书同名 | 另一本文档加入同名“老王”后，查询当前文档仍只返回当前 job 的两个候选；跨 job 候选 ID 按未知人物拒绝 |

成功命中关系时的事件顺序为 `retrieval → delta → final → done`。两条引用分别核对原文
“老王和阿Q是朋友”和“老王帮助阿Q”，`document_id`、`chunk_id`、quote 均与当前已发布版本一致。

## 结论

T036 场景矩阵已覆盖。关系模式的固定状态提示、结构化歧义选择、范围隔离、引用核验及普通聊天回归符合当前契约。
