# Implementation Plan: 叙事文本的场景分块与人物关系抽取

**Branch**: `010-narrative-scene-chunking-and-relation-extraction` | **Date**: 2026-09-06
| **Spec**: [spec.md](./spec.md)（2026-09-06 审核修订版）

## Summary

两条路，一个交付物：

1. **场景切分**（US1）：叙事文本按章节/场景边界切，能装进硬上限的场景优先保持完整；
   超长场景按段落→句子→字符**依次降级**，硬上限优先于场景完整性。
2. **关系抽取**（US2/US3）：逐块抽出带出处与叙述顺序的关系记录，别名归一，
   关系变化**新增不覆盖**。
3. ⭐ **交付物是两个数字**（US4）：一本完整小说的抽取成本，与冻结真值集上的精确率/召回率。

技术路线由 [research.md](./research.md) 定死：本地 `qwen2.5:14b` 主跑 + `7b` 对照（R1）；
异步且**独立于文档处理的任务链**（R2）；五道闸（R3）；两本书分工、真值集调优前冻结（R4）；
关系落在 `knowledge` 模块（R6）。

⚠️ **本功能不改善检索。** 它加的是一条**待验证的补充路径**——结构化抽取能不能补上有限
topK 覆盖不到的跨章节证据，答案要靠 US4 的数字说话，不是靠这份 plan 断言。

## ⭐ 本期与 006~009 的量级差异

**这是第一次把生成式模型调用引进入库链路。** 前四期宪法第 V 条的
「LLM 降级/超时/开关」全部判 N/A，依据是"没有引入模型调用"。本期一引入，
那半条**立刻从 N/A 变成硬要求**：

| 宪法要求 | 本期形态 | 落点 |
|---|---|---|
| 关闭开关 | 叙事模式与抽取**默认关闭**，用户显式启用 | FR-021 |
| 超时上限 | 五道闸（单块 60s / 重试 2 / 熔断 5 / 500 块 / 2 小时） | FR-026 |
| 失败降级 | 抽取失败 → 文档仍 ready、事实检索仍可用 | FR-018 / SC-008 |

另一处量级差异：**抽取结果不确定**。同一块文本两次抽取可能不同，
所以本期**不可能有"逐字节一致"的门禁**去守抽取产物——这与 006~009 完全不同。
可确定性验证的只有**切分**那一半（US1）与**账目/指标的计算过程**（给定同一份原始输出，
指标必须可重算，见 SC-007 的 Independent Test）。

⚠️ **抽取质量不进门禁**——它不确定，进门禁只会天天红。它由 US4 的指标度量。

**Constraints**：
默认关闭时行为与改动前**逐字节一致**（FR-021 / SC-009）；
硬上限与单文档片段数上限**不放宽**（FR-003）；
关系查询**不得绕过**既有的知识库/文档范围与权限（FR-024）；
抽取失败**不得**让文档不可用（FR-018）。

**Scale/Scope**: `internal/knowledge`（第 2 层）+ `internal/db`（第 0 层），
对话接入走既有的 `conversation`(4) → `knowledge`(2) 依赖边。**0 个新增依赖边**。

### 已知范围边界

1. **抽取质量没有门禁，只有指标**。它不确定，无法逐字节比对。这与 006~009 每一期都有
   门禁兜底不同——**本期的质量保证薄得多，报告必须承认这一点**。
2. **不做完整指代消解**（FR-020）。"他/她/那个年轻人"这类指代不解，一部分关系抽不到——
   **这会体现在召回率上，属于已知且被度量的缺口**，不是隐藏缺陷。
3. **性格总结不在本期**（规格审核时移出）。它需要额外的聚合与评价口径。
4. **`knowledge` 模块会更大**（R6 的代价）。将来关系这块真长起来再拆，不是现在。

## 降级与失败矩阵

| 情形 | 行为 | 依据 |
|---|---|---|
| 未启用叙事模式 | 全链路与改动前**逐字节一致**，不入抽取队列 | FR-021 / SC-009 |
| 章节结构识别不出 | 降级为既有分块，章节号**留空**，不得用片段号冒充 | FR-004 / FR-008 |
| 场景超硬上限 | 段落 → 句子 → 字符依次降级，正文不遗漏 | FR-002 |
| 单块抽取超时/失败 | 重试 2 次；仍失败则跳过该块并记账，任务继续 | FR-026 |
| 连续 5 块失败 | 整任务中止，标为失败/中断，**已成功部分保留** | FR-026 / Edge Cases |
| 达到块数或时长上限 | 停止新增调用，标为**部分完成**，已产生用量仍计入账目 | FR-026 |
| 抽取整体失败 | 文档仍 ready、事实检索仍可用 | **FR-018 / SC-008** |
| 关系查询无记录 | 明确说"当前抽取记录中未找到"，**不得**等同于原书没有 | FR-010 |
| 抽取未完成时查询 | 同时说明**覆盖不完整** | FR-010 / FR-022 |
| 文档重处理 | 续跑绑定内容版本 + 配置版本，**不混用新旧** | FR-023 |
| 文档/知识库删除 | 相关人物、关系、出处**不再可查**；晚到任务不得重新发布 | FR-023 |
| 别名归属不可靠 | **单独保留**，不合并 | FR-013 / SC-005 |

## 进入 `/speckit-tasks` 前待拍板

1. **抽取 prompt 的输出结构**：一次抽一块，输出什么形状的结构化结果。
   这直接决定结构校验（FR-009 整块丢弃）怎么写，以及真值集的比对口径。
2. **真值集的标注规模**：《阿Q正传》9 章全标，还是标前 N 章？
   全标更有说服力但人工成本高；标少了分母太小、指标抖动大。
3. **场景分隔符的识别规则**：《西游记》没有现代小说的 `***` 分隔符，
   章内靠什么切场景（还是干脆只切到章 + 段落）。⚠️ 这条直接影响 US1 能不能验收。
