## R1 · 抽取模型：本地 `qwen2.5:14b`，并与 `7b` 做对照（对应 D-002 的一半）

**Decision**：抽取走本地 Ollama，主模型 `qwen2.5:14b`（q4，9.0 GB），
**同时用 `qwen2.5:7b`（4.7 GB）跑一遍同样的真值集**。

**Rationale**：

1. **本地跑把"成本"从钱变成时间**，可以放开跑全书而不用心疼账单。M1 Pro / 32GB 上
   14B q4 跑得动；粗估单块（约 1000 字输入 + 结构化输出）10~15 秒。
2. **两个模型跑同一套真值集，产出的是"选型判断"而不是"跑通汇报"**。
   「7B 精确率 X、14B 精确率 Y、耗时差 Z 倍」比任何单个数字都有价值——
   它回答的是"这个任务需要多大的模型"，而那才是真正要决策的事。
3. 中文叙事 + 结构化输出，Qwen2.5 系列是本地可得选项里最稳的。

**⚠️ 必须记的前提**（FR-017）：所有数字只在 **这个模型 / 这本书 / 这个规模** 下成立。
脱离三者引用等于造谣。

**Alternatives considered**：

| 方案 | 否决理由 |
|---|---|
| 调用商业 API（GPT/Claude） | 成本数字会好看，但**跑全书要真花钱**，且把"值不值得"的判断绑死在某家定价上。本地跑先把量级摸清，将来换 API 只是把账目里的 token 数乘以单价 |
| 只跑 14B | 拿到一个数字，回答不了"要不要更大/更小的模型"——而那是唯一需要决策的问题 |
| 微调一个抽取模型 | 本期是**摸底**不是优化。没有底就不知道该不该微调 |

## R2 · 异步，且做成**独立任务链**（对应 D-002 的另一半 + FR-018 / FR-022）

**Decision**：关系抽取是 `ProcessDocument` **完成之后**的一条独立 asynq 任务，
**不是文档处理的一个步骤**。

**Rationale**：

⭐ 这个选择不只是"别阻塞 HTTP"。**它让 FR-018（抽取失败不能让文档不可用）变成结构性成立
而不是靠代码去守**：文档早就 ready、事实检索一直活着，抽取挂了只是少一份关系数据。

这与 008 把写入前移到 `MarkDocumentPublishing` 是同一个思路——**把约束设计进结构里**。
如果把抽取塞进 `ProcessDocument`，就得在里面到处写 `if 抽取失败 { 不要影响主流程 }`，
那种守护迟早会被某次改动破坏，而且破坏时没有任何报错。

FR-011（可中断可续跑）与 FR-022（抽取状态独立于索引状态）也由此自然落地：
它本来就是另一条任务、另一套状态。

**⚠️ 宪法第 V 条在本期从 N/A 变成硬要求**（原文："引入 LLM 参与检索链路时，
**必须**同时定义失败降级路径、超时上限和关闭开关"）。三者本期的形态：

| 要求 | 本期形态 |
|---|---|
| **关闭开关** | FR-021：叙事模式与关系抽取**默认关闭**，用户显式启用 |
| **超时上限** | 见 R3 的五道闸 |
| **失败降级** | 抽取失败 → 文档仍 ready、事实检索仍可用；查询侧如实说明"覆盖不完整" |

## R3 · 五道闸（对应 FR-026）

| 闸 | 值 | 理由 |
|---|---|---|
| 单块抽取超时 | **60s** | 本地 14B 单块 10~15s，4 倍余量。超了是卡住不是慢 |
| 单块重试 | **2 次** | 再多是浪费——同一块连错三次不会第四次对 |
| 连续失败熔断 | **5 块** | 连续 5 块失败 = 模型或 prompt 坏了，不是偶发。整任务中止并标为失败/中断 |
| 单文档块数上限 | **500 块**（约 50 万字） | 超过说明选错书了 |
| 单文档总时长 | **2 小时** | 硬闸。没有它，一本 700 万字的书会跑一星期 |

**本地模型没有金钱成本，所以时长闸代替成本闸**——但账本（调用次数/耗时/token 用量）
照记（FR-015）。将来换 API 时，那些数字乘以单价就直接是钱。

⚠️ FR-015 要求**区分模型调用耗时与作业墙钟耗时**，且**费用缺失要标"未知"不得填零**。
本地跑的费用就是"未知/不适用"，不是 0——写 0 会让人以为量过了。

## R4 · 真值集：两本书分工（对应 D-003）

**Decision**：

| 书 | 用途 | 规模 | 出处 |
|---|---|---|---|
| **《西游记》第 1–20 回** | 跑**成本/耗时**数字 | 149,179 字、422 段 | Project Gutenberg #23962（公版） |
| **《阿Q正传》** | 标**真值集**算精确率/召回率 | 22,776 字、9 章 | 中文维基文库（`Pd/1996`、`PD-China`） |

**Rationale**：两件事对语料的要求相反。成本数字要**够长**才有意义（短文本测不出线性增长和
熔断行为）；真值集要**够短且人物少**，否则人工标不动——而标不动就没有精确率，
这一期的核心产出直接归零。

**⭐ FR-016 的硬要求：真值集必须在任何 prompt 调优之前冻结。**
不冻结，刷 prompt 刷到真值集上，数字就是自欺——**而且是那种看起来很漂亮的自欺**。

**判定口径**（不定死则数字无意义）：一条抽出的关系算命中，当且仅当**四项全对**——
① 两个实体都归到真值集里的同一人物；② 关系类型落在真值集允许的同义集合内；
③ **方向正确**（「A 是 B 的师父」≠「B 是 A 的师父」）；④ 出处能在原文中定位到。
统计**只在被完整标注的章节范围内**进行；未标注章节的输出**不计为误报**（FR-016 明文）。

⚠️ **口径本身是一种选择，报告里要承认这一点**。比如"关系类型的同义集合"怎么划，
换个划法数字就变——这不是可以回避的，只能写清楚。

## R5 · 语料层面已发现的两个真实问题（会直接影响实现）

跑通语料准备时撞到的，都不是假想：

1. **同一本书里回目写法就不一致**：《西游记》里 `第一三回` 与 `第十四回` 并存、
   `第一五回` 与 `第十六回` 并存；且零用的是 **`○`（U+25CB 白圆圈）而不是 `〇`（U+3007）**。
   我第一版正则漏了 10 个回目**而毫无察觉**——直到去数才发现是 90/100。
   ⚠️ **章节号是 FR-008 的时间维度，语料层面错了整个真值集都是脏的**，
   而且这种错不会报错。结构识别必须有"回目数是否连续"这类**自检**，不能只写个正则就信它。
2. 前 20 回里有 **18 个段落超过 1000 字**——这些就是现在会被从中间劈开的（US1 的实证输入）。

## R6 · 关系落在哪个模块（影响分层）

**Decision**：落在 `internal/knowledge`（第 2 层），**不新建模块**。

**Rationale**：关系是从 documents/chunks 派生出来的数据，而那两样归 knowledge 所有；
FR-024 要求关系查询遵守既有的文档/知识库范围与权限，那套范围逻辑也在 knowledge 里。
新建模块的话，它仍然要伸手进 knowledge 拿 chunk 和权限，反而制造一条新依赖边。

`conversation`(4) → `knowledge`(2) 是**既有**依赖边，D-004 的对话接入因此**零新增依赖边**。

**代价**（如实记）：`knowledge` 会更大。若将来关系这块继续长（跨书图谱、图算法），
届时拆成独立模块（第 3 层）是正确的动作——**但那要等它真的长起来，不是现在**。
