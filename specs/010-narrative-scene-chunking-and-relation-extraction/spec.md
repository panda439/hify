# Feature Specification: 叙事文本的场景分块与人物关系抽取

**Feature Branch**: `010-narrative-scene-chunking-and-relation-extraction`

**Created**: 2026-09-06

**Status**: Draft（2026-09-06 审核修订；待 plan 冻结技术决策）

**Input**: 让系统能"学会"一本它没见过的书，并回答「A 和 B 是什么关系」「这个人性格如何」
这类需要跨段落综合证据的问题。本期交付人物关系及其叙述变化；性格总结不纳入本期验收。范围：叙事文本按场景切分、逐块抽取带出处与章节号的
三元组、人物别名归一、关系边带时间维度。明确不做：图数据库、图算法、跨书统一人物图、
完整指代消解。

## 问题陈述

Hify 现有的入库链路是为**技术文档**设计的：Markdown 靠标题栈、txt 靠段落、PDF 靠版面。
把一本小说喂进去，会撞上两个层次完全不同的问题。

### 第一层：切分把场景劈开

叙事文本的语义单位是**场景**，不是长度。一个场景横跨 1200 字，而分块上限是 1000 字，
它就被切成两半——两半各自缺失前因或后果，检索出来的上下文是断的。

这与 006 修的"跨页段落被切断"是同一类错误的另一种形态：**用一个物理单位（长度）
去切一个语义单位（场景）**。006 拆掉了"页 = 语义边界"，本期要拆掉"长度 = 语义边界"。

### 第二层：有限片段召回可能遗漏跨章节证据

「A 和 B 是什么关系」可能需要综合多个章节，现有有限 topK 的片段召回未必覆盖这些证据。
结构化抽取是本期要验证的一种补充手段，并不意味着 RAG 原理上无法进行跨片段综合。
关系记录也可能漏抽或误抽，不能将它视为全书真相。性格总结需要额外的聚合与评价口径，本期不交付。

### 因此本期的产出是两条路，不是一条

一条是**事实检索**（场景切分后的向量索引，回答"第三章他去了哪里"），
一条是**跨全书的结构化聚合**（关系三元组，回答"他们是什么关系"）。

### ⭐ 本期最重要的产出不是功能，是两个数字

「实体关系抽取要花多少钱」和「抽出来的三元组有多准」——**这两个数字目前给不出来**，
而它们恰恰是决定这套方案值不值得用的全部依据。功能只是拿到数字的手段。

**成本与抽取质量可以按约定口径测量**：成本可以逐次记账，
精确率可以拿一小段人工标注的真值集算。**本期若交付了功能却交不出这两个数字，
等于没做。**

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在硬上限内优先保持场景完整 (Priority: P1)

用户上传并显式选择叙事模式的小说。能装入既有长度硬上限的场景优先完整保留；
超长场景按段落、句子、字符的顺序降级切分，出处保留同一场景标识。

**Why this priority**: 它是第二层能力的地基——抽取是**逐块**做的，块本身被切断，
抽出来的关系就是残缺的。而且它可以独立交付：只做这一条，叙事文本的检索质量就已改善。

**Independent Test**: 准备包含可容纳场景、超长场景及超长单段的固定样本，分别验证完整保留、降级切分、
硬上限和正文无遗漏；先记录既有实现的实际结果，不预设它在每个样本上失败。

**Acceptance Scenarios**:

1. **Given** 一个有明确边界且长度不超硬上限的场景，**When** 叙事模式入库，**Then** 不因前一个场景占用剩余空间而拆开该场景
2. **Given** 章节标题与场景分隔符，**When** 文档入库，**Then** 片段边界落在这些结构边界上
3. **Given** 一个场景长到无论如何都必须切分，**When** 文档入库，**Then** 长度硬上限仍然生效；优先段落边界，单段超限再按句子，单句仍超限才按字符切分，正文不得遗漏
4. **Given** 非叙事文本（技术文档），**When** 文档入库，**Then** 未开启叙事模式时，行为与本功能上线前**完全一致**

---

### User Story 2 - 能回答"他们是什么关系" (Priority: P1)

用户问「A 和 B 是什么关系」。系统给出的答案基于当前文档版本已完成抽取的跨章节证据，且每条依据都能回溯到原文
的具体位置；关系随剧情变化时，能看出变化过程而不是只有最后一个状态。

**Why this priority**: 验证结构化关系记录能否补足现有有限片段召回的跨章节覆盖。

**Independent Test**: 对一本人物关系明确的小说提问，断言答案覆盖了跨章节的多个证据，
且每条证据都指向真实存在的原文位置。

**Acceptance Scenarios**:

1. **Given** A 与 B 在多个章节有互动，**When** 用户询问两人关系，**Then** 答案基于跨章节的多条证据
2. **Given** 每条关系记录，**When** 查看依据，**Then** 都能定位到具体的原文出处
3. **Given** 关系在剧情中发生转变（如敌对→结盟），**When** 用户询问，**Then** 能看出**变化过程**，而不是只剩最后一个状态
4. **Given** 书里从未提及的两个人，**When** 用户询问其关系，**Then** 系统明确回答"当前抽取记录中未找到",**MUST NOT** 推断为原书不存在；未完成抽取时同时说明覆盖不完整

---

### User Story 3 - 同一个人不被拆成几个人 (Priority: P1)

「李明」「小李」「李先生」在结果里是同一个人，不是三个互不相关的条目。

**Why this priority**: 与 US2 同级。不做归一，关系记录会碎成一堆孤立条目——
**US2 的答案会变成"查无此人"或"只有一条边"，而它看起来完全正常**，没有任何报错。
它是 US2 能否成立的前提，但可以独立验收。

**Independent Test**: 准备一本同一人物有多个称呼的小说，断言这些称呼归到同一个人物下，
且该人物的关系记录合并在一起。

**Acceptance Scenarios**:

1. **Given** 同一人物有多个称呼，**When** 抽取完成，**Then** 这些称呼归到同一个人物
2. **Given** 两个**不同**人物有相似称呼，**When** 抽取完成，**Then** 他们**不**被错误合并
3. **Given** 某个称呼无法可靠归属，**When** 抽取完成，**Then** 单独保留而非强行合并——**宁可碎，不可错合**

---

### User Story 4 - 拿得出成本与精确率的真实数字 (Priority: P1)

对一本完整的公版小说跑完抽取，能报出：这本书花了多少钱/多少次调用/多长时间，
以及在人工标注的真值集上，抽出来的三元组精确率与召回率各是多少。

**Why this priority**: **与前三条同级，甚至是本期真正的交付物。** 没有这两个数字，
这套方案的价值判断无从谈起——"能跑"和"值得用"是两件事。

**Independent Test**: 跑完一本书，产出一份含成本与精确率的报告；保存输入、配置、原始输出及账目快照，指标可从同一快照重新计算；不要求再次调用模型得到相同输出。

**Acceptance Scenarios**:

1. **Given** 一本完整小说，**When** 抽取完成，**Then** 能报出总调用次数、总耗时、总成本
2. **Given** 一份人工标注的真值集，**When** 与抽取结果比对，**Then** 能算出精确率与召回率
3. **Given** 这些数字，**When** 写进报告，**Then** 明确标注它们**在什么模型、什么书、什么规模**下测得——脱离这三者的数字没有意义

---

### Edge Cases

- **没有明显场景分隔符的小说**：只有章节、章内不分场景。切分退化为按章节 + 段落，不得报错
- **章节标题格式千奇百怪**（"第一章" / "1." / "楔子" / 无标题）：识别不出时降级，不得编造章节号
- **对话密集的段落**：连续短行，容易被误判为分隔符
- **抽取模型返回非法结构**：按 FR-009 整次丢弃并标记该块失败；**绝不能把半截结果当成事实存下去**
- **同一段落抽出矛盾的关系**（A 是 B 的师父 / A 是 B 的敌人）：两者可能都对（不同章节），
  也可能是抽错。带章节号存两条，**不做仲裁**
- **超长的书**：抽取是逐块的，成本随长度线性增长；必须能中断与续跑，不能只有"从头再来"
- **抽取过程中失败**：保留已校验成功的部分并标明未完成；续跑只处理未成功部分，重复执行不得重复增加关系证据

## Requirements *(mandatory)*

### Functional Requirements

**场景切分（US1）**

- **FR-001**: 系统 MUST 支持按叙事结构（章节、场景分隔）切分，而非仅按长度
- **FR-002**: 有明确边界且能容纳于硬上限内的场景 MUST 完整保留；超长场景 MUST 依次按段落、句子、字符降级切分。硬上限优先于场景完整性，所有子片段 MUST 保留同一场景标识且正文无遗漏；重叠内容不得导致关系证据重复计数
- **FR-003**: 既有的长度硬上限与单文档片段数上限 MUST 继续生效，不得放宽
- **FR-004**: 结构无法识别时 MUST 降级为既有行为，MUST NOT 编造章节或场景边界
- **FR-005**: 非叙事文本的处理行为 MUST 保持不变

**关系抽取（US2）**

- **FR-006**: 系统 MUST 从文本中抽取人物之间的关系，产出结构化记录
- **FR-007**: 每条关系记录 MUST 携带**出处**（可定位到原文的具体位置）
- **FR-008**: 每条关系记录 MUST 携带原文位置及叙述顺序；识别出章节时记录章节序号，无法识别时 MUST 留空，不得以片段号冒充章节号。同章多次变化须能区分；记录新增而非覆盖。章节顺序只表示叙述顺序，不推断倒叙、回忆中的故事时间
- **FR-009**: 抽取结果不合法时，系统 MUST 整体丢弃该次结果，MUST NOT 部分采用
- **FR-010**: 查询输出 MUST 仅基于当前可见、已校验的关系证据；无记录时说明未找到，MUST NOT 等同于原书没有关系。模型抽取可能出错，真实语义正确性由 US4 度量，不承诺任意文本零错误
- **FR-011**: 抽取 MUST 可中断、可续跑，MUST NOT 只支持从头重来

**别名归一（US3）**

- **FR-012**: 有原文依据、可可靠归属的不同称呼 MUST 归到同一人物；同名或同称呼存在多个候选时按 FR-013 保留歧义，不得仅凭称呼相同合并
- **FR-013**: 归属不可靠时 MUST 单独保留而非强行合并——**宁可碎，不可错合**
- **FR-014**: 系统 MUST 记录归一的依据，供事后核查误合并

**成本与精确率（US4）**

- **FR-015**: 系统 MUST 按文档记录关系抽取及别名归一的全部调用尝试（含重试、失败、续跑）、输入输出用量、总耗时与成本。报告区分模型调用耗时与作业墙钟耗时；标注币种及价格版本，费用缺失 MUST 标为未知或估算，不得填零；既有嵌入成本单独列示或明确排除
- **FR-016**: MUST 针对调优前冻结的人工真值集计算精确率（precision）与召回率（recall）；限定在被完整标注的文本范围内统计，按实体、关系类型、方向及有效出处匹配并去重，分母为零报 N/A。保存真值集版本、样本及原始结果，禁止把未标注章节的输出直接计作误报
- **FR-017**: 报告 MUST 标注数字测得的**模型、书目、规模**三个前提

**共同约束**

- **FR-018**: 抽取依赖外部模型调用，因此 MUST 定义失败降级、超时上限与开关；
  抽取失败 MUST NOT 让文档入库整体失败——**事实检索那条路必须仍然可用**
- **FR-019**: 本期 MUST NOT 引入图数据库、图算法、跨书统一人物图
- **FR-020**: 本期 MUST NOT 实现完整的指代消解（"他/她/那个年轻人"级别），只做别名表这一层

- **FR-021**: 默认关闭叙事模式及关系抽取，由用户显式启用；关闭时沿用既有处理路径。未识别结构的文档沿用既有分块，章节留空，仍可按位置追溯。
- **FR-022**: 关系抽取状态 MUST 独立于事实索引状态，区分未启用、待处理、处理中、部分完成、完成、失败/中断；展示已成功处理片段数与总数。仅全部片段成功处理（合法空结果也算成功）才可标为完成。抽取失败不豁免解析或嵌入失败。
- **FR-023**: 续跑 MUST 绑定文档内容版本与抽取配置版本；重复执行不得重复发布关系。文档重处理后不得混用新旧版本，删除文档或知识库后相关人物、关系、出处 MUST 不再可查询，晚到任务不得重新发布。物理清理、并发防护方案在 plan 中定义。
- **FR-024**: 人物归一及关系查询 MUST 限定在所属文档内，并遵守既有访问规则、Agent 知识库及文档范围；不能通过关系查询绕过现有范围限制。跨书同名人物不得合并，书目不明确时澄清或分书展示。
- **FR-025**: 每条关系与归一依据 MUST 关联当前文档版本的实际原文片段及可校验引用位置；不存在或与原文不匹配的引用按 FR-009 拒绝。文本匹配只能证明出处存在，不等于关系语义正确。
- **FR-026**: 抽取 MUST 有明确的超时、重试次数及单文档调用/用量预算；达到预算后停止新增调用并标为部分完成，已产生费用仍计入账目。具体限额及模型在 plan 中冻结。

### 需要在 `plan.md` 中解决的开放决策

- **D-001 · 模式与格式落地**：本期上传时显式选择叙事模式，默认关闭，不做自动分类；覆盖现有 txt、Markdown、PDF 的可解析正文，不新增 OCR。plan 定义入口、持久化、结构识别规则及稳定的片段/场景位置表示。
- **D-002 · 抽取用什么模型、在哪调用**：入库链路在既有嵌入调用之外新增生成式关系抽取调用，宪法第 V 条的"降级/超时/开关"
  从 N/A 变成**必须满足**。同步还是异步、失败重试策略、成本上限如何设。
- **D-003 · 真值集怎么建**：选哪本公版书、标注多大规模、精确率与召回率的判定口径
  （关系类型算不算错？出处算不算？）。**口径不定死，算出来的数字就没有意义。**
- **D-004 · 对话接入**：本期沿用既有对话入口回答人物关系并展示出处及覆盖状态，不新增独立关系管理界面。plan 定义查询路由、书目歧义提示、记录选择与上下文预算；截断时不得声称覆盖全部证据。

### Key Entities

- **场景（Scene）**：叙事文本的语义单位，由章节与场景分隔界定。片段的边界应当尽量与它对齐
- **人物（Character）**：一个实体，可能有多个称呼。别名归一的产物
- **关系记录（Relation Record）**：一条「谁 · 和谁 · 什么关系 · 第几章 · 出处」的结构化事实。
  它保留叙述顺序与出处；不同记录可能是变化、并存关系或抽取错误，不假定每条都为真，也不把章节当作故事时间
- **抽取账目（Extraction Ledger）**：一次抽取花了多少调用、多少时间、多少钱

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 固定样本内，能容纳的明确场景保持完整；超长场景、单段、单句按 FR-002 降级，全部片段（含 overlap）不超硬上限且正文无遗漏；与既有结果对照报告
- **SC-002**: 「A 和 B 是什么关系」的答案覆盖**跨至少两个章节**的证据，且每条证据可定位到原文
- **SC-003**: 关系发生转变时，能看出**至少两个不同章节的不同状态**，而不是只剩一个
- **SC-004**: 冻结的有明确归属依据样本中，同一人物多个称呼呈现为一个人物；歧义样本单独保留并可查看依据
- **SC-005**: 冻结的同名、相似称呼和歧义反例集中，错误合并数为 **0**；真实书目另报误合并数与样本规模，不宣称通用零误合并
- **SC-006**: ⭐ 能报出一本完整小说的抽取**总调用次数、总耗时、总成本**
- **SC-007**: ⭐ 能报出三元组在冻结人工真值集上的**精确率与召回率**，并标注模型/书目/规模
- **SC-008**: 抽取失败时，事实检索那条路**仍然可用**——文档不因抽取失败而整体不可用
- **SC-009**: 非叙事文本的检索行为与改动前**完全一致**；既有确定性门禁逐字节不变，另用 txt/Markdown/PDF 默认关闭模式样本比对分块内容、顺序及元数据

- **SC-010**: 抽取中断后续跑与重复任务不重复增加关系；失败、预算耗尽、非法输出均显示真实覆盖状态，未完成时不得声称全书结论。
- **SC-011**: 删除、重处理和晚到任务场景下，已删除或旧版本关系不可见；Agent 范围外记录不可查询，跨书同名不混合。
- **SC-012**: 无章节、同章多次关系变化、倒叙样本可定位并按叙述顺序展示，不编造章节号或故事时间。

## Assumptions

- **两条路的价值不对称**：场景切分（US1）即使单独交付也有价值；关系抽取（US2/US3）
  必须三条一起才成立——切分不准则抽取的输入是残缺的，别名不归一则关系记录是碎的。
- **⭐ 成本与精确率是本期的交付物，不是副产品。** 只交付功能、给不出这两个数字，视为未完成。
- **精确率不会很高，这是预期而不是失败**。模型辅助抽取，
  在长篇叙事上出错是常态。**本期要的是知道它错到什么程度**，不是让它不错。
- **关系的"真值"本身是有争议的**。人物关系的判定带主观性，真值集的标注口径必须写死，
  且报告里要承认这个口径本身是一种选择。
- **不做完整指代消解**是明确的能力上限。"他/她/那个年轻人"这类指代不解，
  意味着一部分关系抽不到——这会体现在召回率上，属于**已知且被度量**的缺口。
- **抽取是可续跑的离线工作**，不在检索或对话的实时路径上。
- **沿用既有的检索、融合、准入、重排、邻接逻辑**：本期不碰它们（SC-009 由既有门禁证明）。
