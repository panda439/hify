## 本轮新拍板的两项

### 裁定 1 · 抽取输出结构与校验

单块抽取输出一个 JSON 对象：

```json
{"relations":[{"subject":"赵太爷","object":"阿Q","type":"雇佣","evidence":"原文里的一句话"}]}
```

**校验规则（任一不过 → 整块丢弃，FR-009）**：
① JSON 能解析且顶层是对象、`relations` 是数组；
② 每条四个字段齐全且非空；
③ `type` 落在封闭集合内；
④ ⭐ **`evidence` 必须能在该块原文中原样找到**。

⭐ 第 ④ 条是**最便宜的反幻觉手段**，也是 FR-025（引用必须与原文可校验匹配）的直接实现：
模型编出来的"原文"几乎不可能与真实文本逐字相同。
⚠️ 但它**只能证明出处存在，不能证明关系语义正确**——后者由 US4 的精确率度量，
报告里不得把"引用可校验"说成"抽得准"。

### 裁定 2 · 场景边界规则

**场景边界 = 章节边界 ∪ 显式分隔符**（`***` / `———` / `※` / 连续 ≥2 个空行）。
章内没有显式分隔符时，**整章即一个场景**。

⚠️ **由此产生一个必须正视的验收问题**：《西游记》每回约 7,500 字、《阿Q正传》每章约 2,500 字，
**都远超 1000 字的分块上限**。也就是说在这两本书上，「场景完整保留」这条路径
**几乎不会被触发**，实际走的一直是「章节 → 段落降级」。

因此 **SC-001 的"能容纳的场景保持完整"必须用构造夹具验证**（短场景 + 显式分隔符），
不能指望真实语料覆盖到。**不构造夹具就等于这条根本没验**，而它会看起来像验过了。

风险最低。
